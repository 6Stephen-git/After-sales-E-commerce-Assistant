# Git 工作流规范

> 本文件为项目的 Git 操作规范。Coding Agent 不直接执行 git 命令。

## 分支策略


| 分支           | 用途   | 说明                      |
| ------------ | ---- | ----------------------- |
| `main`       | 稳定分支 | 只接受 `dev` 合并，不直接提交      |
| `dev`        | 开发主线 | 所有功能分支的合并目标             |
| `feat/<模块名>` | 功能分支 | 从 `dev` 拉出，完成后合并回 `dev` |
| `fix/<问题描述>` | 修复分支 | 从 `dev` 拉出，修复后合并回 `dev` |


## 提交信息格式

(): <简短描述>


| type    | 含义  |
| ------- | --- |
| `feat`  | 新功能 |
| `fix`   | 修复  |
| `docs`  | 文档  |
| `test`  | 测试  |
| `chore` | 杂项  |


## 合并流程

1. 在 `feat/<模块名>` 分支完成开发与测试
2. 推送到远程，发起 Pull Request 合并到 `dev`
3. 合并后删除 `feat` 分支
4. 阶段里程碑达成时，`dev` 合并到 `main` 并打 tag

## 标签与版本

- 格式：`v<主版本>.<阶段>.<迭代>`
- 与 `Roadmap.md` 中的里程碑对应
- 示例：`v0.1.0` 初始化完成，`v0.2.1` Agent 1 完成，`v1.0.0` MVP 发布
