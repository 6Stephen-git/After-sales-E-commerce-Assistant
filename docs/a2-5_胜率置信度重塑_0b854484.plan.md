## 新决策机制

### 处置方向（取代三策略）

新增枚举常量（`schemas.py`）：

```python
DISPOSITION_DEFEND = "defend"          # 主动抗辩，引导平台介入
DISPOSITION_NEGOTIATE = "negotiate"    # 协商处理，保留后续空间
DISPOSITION_COMPENSATE = "compensate"  # 主动善后，快速止损
VALID_DISPOSITIONS = [DISPOSITION_DEFEND, DISPOSITION_NEGOTIATE, DISPOSITION_COMPENSATE]
```

`StrategyOutput` 中 `strategy` 字段重命名为 `disposition`，值域不变，前端展示逻辑不受影响。

### 处置方向决定逻辑（新的 `_determine_disposition`）

优先级规则链，顺序判断命中即返回，规则站位来源 MySQL，不依赖本地文案关键词：

```
1. 恶意层 risk_level == "high"
   → disposition = defend
   （无论是否存在商责信号，恶意高风险优先保护商家风险敞口）

2. 恶意层 risk_level == "medium" 且 商责明确信号同时存在
   → disposition = negotiate
   （两侧信号冲突，不能直接赔、也不能直接抗辩，先谨慎协商）

3. 恶意层 risk_level == "medium" 且 证据质量 == low（无商责明确信号）
   → disposition = defend
   （有风险信号且我方证据弱，先补证控损）

4. 商家过失明确信号（规则站位偏买家 + 证据 high + 恶意 low）
   → disposition = compensate
   （商责清楚、对方无恶意，快速善后止损）

5. 客户价值通道触发（long_term 或 order）且 恶意层 risk_level == low
   → disposition = negotiate（优先维护关系）

6. 其余所有情况（规则中性、信息不足、无强覆盖条件）
   → disposition = negotiate（默认保守协商）
```

**商责与恶意同时存在的处理原则：**

| 组合 | 处置 | 理由 |
|---|---|---|
| 恶意 high + 商责明确 | defend | 恶意高风险优先，不向恶意买家主动让利 |
| 恶意 medium + 商责明确 | negotiate | 双侧信号冲突，谨慎协商，不轻易赔也不硬抗 |
| 恶意 low + 商责明确 | compensate | 商责清晰，正常善后 |
| 恶意 high + 商责不明确 | defend | 商家侧无明显过失，全力抗辩 |

### 恶意层备注（high / medium 必须显式输出到 risk_factors）

- `risk_level = high`：「高风险恶意：优先抗辩并准备平台介入，先固定证据链后再沟通」
- `risk_level = medium`：「中风险恶意：谨慎协商；若证据质量 low，则先走抗辩补证路径」
- `risk_level = low`：不额外输出备注

### 胜率计算（新的 `_estimate_win_rate`）

**胜率含义**：仅在 `disposition = defend` 时计算，表示"抗辩获得平台支持商家的概率"。

- `disposition = defend`：返回 `estimated_win_rate`（0.05~0.95）
- `disposition != defend`：`estimated_win_rate = None`，不展示，避免误导

四轴独立打分后加总：

| 轴 | 字段来源 | 满分贡献 |
|---|---|---|
| 规则站位强度 | MySQL 规则命中数量 + 站位明确度 | 0.40 |
| 证据质量 | `facts.evidence_quality` + `missing_evidence` 完整度 | 0.25 |
| 强信号修正 | 恶意风险等级（抗辩可行性修正） | 0.20 |
| 判例支撑度 | `similar_cases` 方向一致数量 | 0.15 |

**规则轴（满分 0.40）：**
- 站位明确偏商家，命中 >= 2 条 → 0.40
- 站位明确偏商家，命中 1 条 → 0.28
- 中性/弱命中 → 0.16

**证据轴（满分 0.25）：**
- evidence_quality=high 且 missing_evidence 为空 → 0.25
- evidence_quality=medium 或少量缺失 → 0.16
- evidence_quality=low 或关键证据缺失 → 0.07

**强信号轴（满分 0.20）：**
- 恶意 high → 0.20（买家侧风险显著，抗辩成功率上修）
- 恶意 medium 且证据 low → 0.14
- 恶意 medium 且证据非 low → 0.10
- 恶意 low → 0.06
- 若同时存在商责明确信号（规则偏买家+证据 high）→ 在上述基础额外扣减 0.08，下限为 0

**判例轴（满分 0.15）：**

"方向一致"定义：`outcome` 含"支持商家"或 `merchant_action` 含"抗辩"，且 `similarity >= 0.6`

- 命中 >= 2 条一致判例 → 0.15
- 命中 1 条一致判例 → 0.09
- 无相似判例（列表为空或均 similarity < 0.6）→ 0.04（保底分，不惩罚）
- 无判例时不影响 disposition 判定，判例轴仅作辅助修正

`win_rate = clamp(规则轴 + 证据轴 + 强信号轴 + 判例轴, 0.05, 0.95)`

### 置信度计算（新的 `_estimate_confidence`）

**置信度含义**：当前输入信息是否足够支撑做出可靠决策，与胜率正交，不表达"谁更可能赢"，仅告知商家"当前判断有多确定"。

三维各自独立打分后加总：

**维度一：规则确定性（满分 0.40）**

| 情况 | 得分 |
|---|---|
| 规则站位明确（偏商家或偏买家），命中 >= 1 条 | 0.40 |
| 规则命中但站位中性 | 0.20 |
| 无规则命中 | 0.08 |

**维度二：证据充分性（满分 0.35）**

| 情况 | 得分 |
|---|---|
| evidence_quality=high 且 missing_evidence 为空 | 0.35 |
| evidence_quality=medium 或 missing_evidence 非空但 <= 1 项 | 0.20 |
| evidence_quality=low 或 missing_evidence >= 2 项 | 0.07 |

**维度三：信号一致性（满分 0.25）**

| 情况 | 得分 |
|---|---|
| 规则/恶意/判例信号方向一致，无矛盾 | 0.25 |
| 部分矛盾（如规则偏商家但判例偏买家） | 0.13 |
| 主要信号矛盾（恶意 high/medium 与商责明确信号同时存在） | 0.05 |

信号矛盾时，系统必须在 `reasoning` 中明确说明冲突原因，不能静默处理。

`confidence = clamp(维度一 + 维度二 + 维度三, 0.10, 0.95)`
