# 数据库设计规范

## 数据库
MySQL  所有商家数据通过 `merchant_id` 实现租户隔离。

## 核心实体
系统需要持久化以下数据实体，具体表结构和字段设计由开发决定：

- **商家配置**：存储模式选择、自动化阈值等偏好
- **纠纷判例库**：存储每次纠纷复盘产生的经验卡片，按 `merchant_id` 隔离
- **买家画像**：基于商家自有订单数据聚合，买家标识使用手机号 SHA256 哈希
- **平台规则库**：存储公开争议处理规则，全局共享
- **话术模板库**：系统默认模板全局共享，商家可新增自定义模板

## 硬约束
- 所有涉及商家数据的查询必须包含 `WHERE merchant_id = ?`
- 买家手机号使用 SHA256 单向哈希存储，不可存明文
- 仅 Agent 5 可写入判例库，其他 Agent 只读或无权访问
- 数据库连接信息通过环境变量配置，禁止硬编码
- 表结构变更必须记录在 Changelog 中
- **向量库补充**：判例库中 `lesson_text` 字段可选择向量化后存入 ChromaDB，作为语义检索补充。此为可选能力，MVP 阶段可不部署。向量库不可用时，Agent 2 降级为纯标签检索。
